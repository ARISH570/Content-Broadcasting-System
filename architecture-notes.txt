Architecture Notes for Content Broadcasting System
=================================================

Authentication and RBAC
- JWT-based authentication protects teacher and principal routes.
- Roles supported: `teacher` and `principal`.
- `verifyToken` handles authentication.
- `checkRole` enforces role-based access.

Content and Scheduling Model
- Content is grouped by subject such as Maths or Science.
- Each subject uses its own `ContentSlot`.
- Rotation is subject-specific and time-window aware.
- The public API returns active approved content for a teacher.

Upload Design
- Multer handles uploads.
- Allowed file types: JPG, PNG, GIF.
- Max file size: 10MB.
- File metadata is stored in MySQL through Sequelize.

Approval Workflow
- Content moves through `uploaded -> pending -> approved/rejected`.
- Only principals can approve or reject content.
- Rejection requires a reason.
- Only approved content can become live.

Rotation Logic
- Content must be within `start_time` and `end_time` to be active.
- Each content item has a rotation duration in minutes.
- Rotation repeats continuously within each subject group.
- Active content is chosen from the current cycle position.

Database Decisions
- MySQL with Sequelize ORM.
- Tables: `Users`, `Contents`, `ContentSlots`, `ContentSchedules`.
- Relations are modeled with foreign keys.
- Status and role fields use enums for integrity.

Database Configuration
- `DB_MODE=local` uses local MySQL variables.
- `DB_MODE=railway` uses Railway MySQL variables.
- Apps outside Railway, such as Render, should use `MYSQL_PUBLIC_URL`.
- Apps inside Railway can use `MYSQL_URL`.

Code Structure
- `src/controllers`: API business logic.
- `src/models`: Sequelize models and associations.
- `src/routes`: Express route definitions.
- `src/middlewares`: auth and role guards.
- `src/services`: scheduling logic.
- `src/config`: database configuration.

Scalability Notes
- Database-backed metadata keeps the app stateless.
- JWT auth avoids server-side sessions.
- Local uploads can later move to S3 or another object store.
- Scheduling logic is isolated in a service for easier extension.
- Redis caching can be added later for the public API.

Deployment Notes
- Local development uses local MySQL.
- Production API is deployed on Render.
- Production MySQL is hosted on Railway.
- Render connects to Railway through `MYSQL_PUBLIC_URL`.
